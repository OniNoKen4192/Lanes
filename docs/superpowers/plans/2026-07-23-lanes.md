# Lanes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extract the proven cross-model KEEP/DELEGATE workflow from `S:\GirlsSchedulingProject` into a portable, project-agnostic Claude Code plugin (`S:\Lanes`) distributed as a self-contained GitHub marketplace repo.

**Architecture:** A single repo that is both a Claude Code plugin and its own marketplace. All *behavior* (two agents, two commands, one skill, generic ROUTING + spec-template files) ships generic in the plugin and is never copied into consuming projects. All *facts* live in the consuming repo as `AGENTS.md` + `.lanes/config.md`. Generic files reference project facts by config field name; agents/commands resolve `${CLAUDE_PLUGIN_ROOT}` at runtime to read the generic templates. v1 ships one working DELEGATE backend (Codex via MCP) behind a single documented seam.

**Tech Stack:** Markdown prompt/skill/command authoring + two JSON manifests. No compiled code, no runtime. The "tests" are structural acceptance checks (JSON validity, leaked-string greps, cross-reference integrity) run with Bash.

**Source of truth (read fresh at task time — do not work from memory):**

  `git -C "s:/GirlsSchedulingProject" show master:AGENTS.md`,

  `... master:docs/superpowers/tasks/TEMPLATE.md`.
- WIX agents/command (untracked, on disk):
  `s:/GirlsSchedulingProject/.claude/agents/codex-implementer.md`,

- The approved design spec: `docs/superpowers/specs/2026-07-23-lanes-design.md`.

## Global Constraints

- **Vocabulary is fixed:** the two lanes are **KEEP** (frontier Claude — planning, review, security-critical work) and **DELEGATE** (subscription-pool backend). Never use the original `CLAUDE`/`CODEX` labels in any shipped file. Lane markers in plans are `(LANE: KEEP)` and `(LANE: DELEGATE, tier <t>)`.
- **Generic-behavior files must contain zero WIX/stack specifics.** The five generic-behavior files — `templates/ROUTING.md`, `templates/TEMPLATE.md`, `agents/lanes-implementer.md`, `agents/lanes-reviewer.md`, `commands/lanes-emit.md`, `commands/lanes-init.md`, `skills/lanes/SKILL.md` — are checked against this **DENYLIST** (case-insensitive, whole-word where sensible):
  `wisconsin-ice-exchange`, `wix`, `wix-postgres`, `wix_test`, `pnpm`, `vitest`, `playwright`, `prisma`, `neon`, `resend`, `shadcn`, `3.8.5`, `3100`, `next.js`, `nextauth`, `src/auth.ts`, `src/lib/authz.ts`, `src/lib/availability.ts`, `seededSchedulerEmail`, and the WIX workflow-ID tokens (`a1`–`a8`, `o1`–`o4`, `s1`–`s11`, `v1`–`v3`), and the WIX tier names as literals (`sol`, `terra`, `luna`). Backend references to **Codex / MCP / `mcp__codex__*`** are permitted only in the two agents (the seam) and the README/config example — never in ROUTING/TEMPLATE/skill.
- **`config.example.md` and `README.md` are exempt** from the DENYLIST: the config example illustrates with real WIX values by design, and the README names Codex as the shipped backend. They have their own acceptance checks.
- **Faithfulness over improvement.** This is an extraction. Preserve every load-bearing discipline from the source files (verbatim-spec dispatch, git-derived scope audit, scope-is-a-gate, no-clobber, RATE_LIMITED never-self-implement, reviewer-never-writes). Do not "improve" the pipeline's logic; only genericize its facts. Any genuine improvement is a separate, flagged proposal — not folded in silently.
- **Runtime file resolution pattern:** wherever a generic command/agent must read a plugin-shipped file, it does so via `${CLAUDE_PLUGIN_ROOT}` (e.g. `cat "${CLAUDE_PLUGIN_ROOT}/templates/ROUTING.md"`), and reads project facts from the consuming repo's `.lanes/config.md` and `AGENTS.md`. Never hardcode an absolute plugin path.
- **Commit after every task** with a `feat:`/`docs:` message. This repo is not yet under git; Task 1 initializes it.
